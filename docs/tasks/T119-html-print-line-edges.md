## Goal
Two HTML print details. After a forced page break, the first printed baseline sits where the
PDF's does. And, if D18 chooses it, each HTML style carries a paint-time shift `top: −c` so that
screen gaps equal Word's model; otherwise c per style is stated as design.md §0.4's
exception 11 and this task only fixes the forced break.

## Read first
- `docs/spec/design.md` §0.3 ("Agreement"), §0.4 (exception 11)
- `docs/research/R13-single-source-defaults.md` §3.2 (HTML line edges, probe residual)

## API to implement
None: the shift is generated from each style's size, line height and the shipped metrics: T106's
`src/design/metrics.toml` holds, per family, the hhea and OS/2 typo and win ascent and descent
that Chrome uses, besides s and A.

## Steps
1. A rule for the first block after `.page-break`: static in `print.css` where it does not depend
   on c, generated by `src/html/design.rs` from T106's metrics where it does.
2. If D18 compensates: generate c per style and write `position: relative; top: −c`, on an
   inner element for bordered or filled blocks.
3. Tests in `tests/html_design.rs`.

## Acceptance criteria
1. After a forced break, the first printed baseline equals the PDF's plus the first block's c
   within 0.5 pt without D18's shift, or the PDF's within 0.5 pt with it (T102's harness). At
   D3 = 1.6, c is about (1.6 − 1.424)/2 × 11 ≈ 0.97 pt for Source Sans 3, more for Libertinus
   Serif or Calibri.
2. If D18 compensates: the screen-layout gaps of the harness's reference documents equal Word's
   model within 0.1 pt.
3. `cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test`,
   `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps` pass.

## Out of scope
- Printed HTML's 0.75 pt baseline grid (print gains the mean, not each gap).
- CSS `text-box-trim` and `text-box-edge`, untested in Chrome.

## Hints (verified)
- `print.css:5` at main: `.page-break { display: block; break-after: page; }` inside
  `@media print`.
- Chrome puts a baseline at round(ascent in px) + floor(half-leading in px) below the box top,
  in CSS px of 0.75 pt (R13 §3.2, probe residual). A relative shift moves paint, not boxes.
- c depends on the platform's metrics source: hhea on macOS; on Windows the win metrics unless
  `USE_TYPO_METRICS` is set. Source Sans 3's hhea and typo metrics agree (1024/−400), its win
  metrics do not (934/288) (R13 §3.2).
