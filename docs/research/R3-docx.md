## 0. Executive summary and recommendation

**Recommendation: hand-roll the package (as `presenter_rs/src/pptx.rs` does for .pptx), with a
pandoc-compatible style vocabulary and a pandoc-style `--reference-doc` that copies parts
verbatim. Do not build on docx-rs.** Reasons, all verified below:

1. docx-rs 0.4.22 has no OMML/equations, no SVG, no raw-XML escape hatch in the body, no
   `w:tblHeader`, no `w:tblCaption`, no `updateFields`, no footnote separator/`w:footnoteRef`,
   re-encodes every image to PNG, reserves numbering id 1 for its own default list, and its
   reader is lossy (round-tripping pandoc's `reference.docx` drops the theme part, `fontTable.xml`,
   `webSettings.xml`, `w:next`/`w:uiPriority`/`w:contextualSpacing`/`w:lang` in styles, the
   `m:mathPr` and `footnotePr` settings, rewrites `sectPr` with its own A4/margins defaults and
   flattens the `Table` style's conditional `tblStylePr firstRow` into an unconditional `tcPr`).
   So a reference doc cannot be honoured through docx-rs. What it does well (paragraph/run
   properties, tables with gridSpan/vMerge, numbering, bookmarks, hyperlinks, footnote bodies,
   TOC with pre-rendered entries, generic field codes) is exactly the part that is easy to write
   by hand, and the XML needed for every feature is captured verbatim in §2 from pandoc output.
2. A hybrid (docx-rs XML + post-processing + own ZIP) is possible because `Docx::build()` returns
   `XMLDocx` with every part as `pub Vec<u8>`, but you would be string-patching OMML, SVG,
   `footnoteRef`, theme parts, content types and rels into XML you do not control; it is more
   code than writing the ~15 element kinds directly.
3. The sibling `pptx.rs` already contains a stored-entry ZIP writer with CRC-32, `escape()`,
   `clean()` (XML 1.0 char filter) and EMU helpers that can be lifted; or use `zip 9.0.5` with
   `default-features = false, features = ["deflate-flate2-zlib-rs"]` for deflated parts.
4. For equations: write a small LaTeX→OMML (or MathML→OMML) emitter following texmath's mapping
   (§4); `tex2word-math 1.0.6` (MIT, zero deps, 1 364 lines) is a usable seed/fallback but is
   coarse (merges runs, no `m:limLow`, no `m:eqArr`, silently drops unknown macros).

## 3. pandoc's `--reference-doc` and style vocabulary

### 3.1 Behaviour (manual + `Writers/Docx.hs`, verified)

Manual: "For best results, the reference docx should be a modified version of a docx file produced using pandoc." / "The contents of the reference docx are ignored, but its stylesheets and document properties (including margins, page size, header, and footer) are used in the new docx."

Source (`collectReferenceEntries`, `miscRelEntries`, `otherMediaEntries`, `copyChildren`, `mkStylesEntry`, `extractPageLayout`):

- **Regenerated by pandoc**: `[Content_Types].xml` and `word/_rels/document.xml.rels` ("from scratch rather than reading from reference.docx"), `word/document.xml`, `word/footnotes.xml` + `word/_rels/footnotes.xml.rels`, `word/comments.xml`, `word/styles.xml` (reference styles + dynamically added missing ones), `word/numbering.xml` (entirely pandoc's), `docProps/core.xml`, `docProps/custom.xml`, `_rels/.rels`.
- **Copied verbatim from the reference**: `docProps/app.xml`, `word/theme/theme1.xml`, `word/fontTable.xml`, `word/webSettings.xml`, `word/fonts/*`, every header/footer part the sectPr references, all `word/_rels/*.xml.rels` except document/footnotes rels, everything under `word/media/`.
- **`word/settings.xml`**: `copyChildren refArchive distArchive "word/settings.xml"` merges a fixed list `settingsElementNames` (includes `updateFields`, `rsids`, `compat`; `footnotePr`/`endnotePr` deliberately excluded) from the reference into pandoc's own settings.
- **`w:sectPr`**: taken from the reference's `document.xml` body (`extractPageLayout`), else `<w:sectPr><w:footnotePr><w:numRestart w:val="eachSect"/></w:footnotePr></w:sectPr>`.
- Missing paragraph styles are added with `w:basedOn="BodyText"`, missing character styles with `BodyTextChar`; `SourceCode` is skipped if a "Source Code" style exists; token styles (`styleToOpenXml`) are based on `VerbatimChar`; dynamic styles only added "if they are missing from the style map (`hasStyleName`)" — matching is by **style name**.

Experiment (verified, `$SB/pandoc-docx/out/amr/`): modified reference with Heading1 `<w:color w:val="FF0000"/>`, a `Callout` style with `pBdr`+`shd`, an A4 `sectPr` and `<w:updateFields w:val="true"/>` → the output kept the Callout definition unchanged (pBdr present), used `<w:pStyle w:val="Callout"/>`, copied the sectPr verbatim (`pgSz 11906×16838`, `pgMar 1134…`), and kept `updateFields`. Output parts: everything in §2.1 incl. `theme1.xml`, `webSettings.xml`.

Custom styles (manual, verified quotes): "If you define a Div, Span, or Table with the attribute `custom-style`, pandoc will apply your specified style to the contained elements" (Div → paragraph style, Span → character style, Table → table style) "with the exception of elements whose function depends on a style, like headings, code blocks, block quotes, or links". "For docx or odt output, you don't need to enable any extensions for custom styles to work." Raw XML: "Use `openxml` for `docx` output" (fenced `{=openxml}` blocks). ### 4.3 Does Word render MathML embedded in document.xml?

No evidence that it does: Word's native model is OMML ("OMML is the XML format that encapsulates the OfficeMath in-memory Professional format"; interoperability with MathML is "via conversion"); a Microsoft Q&A answer about AltChunk/MathML says to convert to OMML and write it into the main part; a python-docx user who pasted MathML text into a run got nothing rendered.     w.create_element("w:t").with_attribute(("xml:space", "preserve"))
```rust
        .write_text_content(quick_xml::events::BytesText::new("x < y & z"))?;   // escapes -> x &lt; y &amp; z
    Ok(()) })?;
let xml = String::from_utf8(w.into_inner())?;       // <w:p w14:paraId="1"><w:t xml:space="preserve">x &lt; y &amp; z</w:t></w:p>
// ElementWriter: with_attributes(iter), write_empty(), write_cdata_content(BytesCData), write_text_content(BytesText); Writer: write_event(Event), write_bom(), get_mut(), into_inner()
// BytesText::from_escaped(already_escaped) for pre-escaped content
```

Manual `format!`/`push_str` with `escape()` (as presenter_rs's `pptx.rs` `escape()` + `clean()` do) is sufficient for writing; quick-xml's `Reader` is the tool for reading the reference docx's `styles.xml` (collect `w:styleId`/`w:name`) and `document.xml` (extract `w:sectPr`).

## 8. Open questions

1. **Word rendering cannot be verified locally in automation** (osascript hung > 20 s). Items that need a manual Word check before release: single-run vs multi-run field codes; `w:footnoteRef` necessity; Unicode bullet without the Symbol font; a docx without `theme1.xml` whose styles reference `majorHAnsi`/`accent1`; whether `w:dirty="true"` on a TOC plus `w:updateFields` prompts once or twice; SVG `svgBlip` with PNG fallback rendering; `w:tblLook w:val="0020"` vs the long-form attributes only.
2. **SEQ Table** instruction text not captured (only `SEQ Figure \* ARABIC ` verified); confirm from `native/word/document.xml` lines ~723–740 before relying on it.
3. **pandoc's `settingsElementNames` list** was only partially extracted (`updateFields`, `rsids`, `compat` confirmed; `footnotePr`/`endnotePr` excluded). If writer copies the reference's `settings.xml` wholesale instead, decide whether to strip `w:footnotePr` (pandoc issue #9522).
4. **Reference numbering**: pandoc regenerates `numbering.xml` from scratch, so a reference whose styles carry `w:numPr` (e.g. numbered headings) would dangle; writer could instead keep the reference's `numbering.xml` and append its own definitions with high ids (pandoc uses 990/991/99411 and numIds ≥ 1000, which avoids collisions with Word-authored files).
5. **Licensing of `reference.docx`**: pandoc's data file is GPL-2; writer should author its own `styles.xml` reproducing the style *names* and similar formatting values rather than vendoring the file (names/values are facts; the XML text is pandoc's).
6. **Math**: write an own LaTeX→OMML (or MathML→OMML from the HTML pipeline's MathML) following §4.1, or fork tex2word-math (MIT) and add `m:limLow`, `m:eqArr`, `m:sty p` operators, `sepChr`/`grow`, unknown-macro errors. Which LaTeX subset is in scope?
7. **TOC strategy**: pre-rendered entries (headings + `PAGEREF` with empty/placeholder page numbers + `updateFields`) vs pandoc's empty dirty field. Pre-rendered gives LibreOffice/QuickLook/Google Docs something to show; page numbers are only right after Word updates fields.
8. **Headers/footers**: only reachable through a reference doc (copy parts + sectPr) unless writer generates `header1.xml`/`footer1.xml` itself (XML not captured here; docx-rs can emit them if an example is needed).
9. **Schema validation**: whether to download the ECMA-376 Part 1/4 ZIPs (schemas not confirmed inside) and wire `xmllint --schema` into an optional test, or install `tex2word` / `dxpdf` as oracles — none tested.
10. **ANSI 256/truecolor** streams: cansi's `Color` enum has no 256-colour/RGB variants; check nbconvert-style fidelity needs before choosing cansi over a vte/anstyle-parse SGR state machine.
